# FAQ 与故障排查

按主题分组的常见问题。每条给出直接答案与依据；涉及算法边界的问题会明确"能做什么、不能做什么"。

## 构建与启动

### 需要什么系统版本？

macOS 15 或更新，Swift 6 工具链；项目在 macOS 26 上验证。无第三方依赖，构建不需要联网。

### test.sh 报找不到 XCTest？

部分 Command Line Tools 安装不包含 XCTest。安装完整 Xcode 即可——`test.sh` 检测到 Xcode 时自动把 `DEVELOPER_DIR` 指向它的工具链。也可手动：

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
```

### 构建脚本说"Guitarget 仍在运行"？

脚本只会**请求正常退出**，不会强杀进程。处理未保存文档的对话框后重试；取消关闭时脚本会故意失败，这是保护数据的预期行为。

### 为什么 Debug 构建里音频代码还是很快？

`GuitarAudio` 目标在 Debug 配置下也显式启用 `-O`：未优化的 YIN 单窗口约 63–65 ms，超过 25 ms 分析周期；优化后约 0.41–0.46 ms。UI 与曲谱模块仍保留普通调试构建。

## 权限与采集

### 拒绝麦克风授权后应用还能用吗？

能。编辑、保存、普通试听与全部浏览功能不要求录音权限；只有点击"开始采集"才请求授权。拒绝后界面显示明确原因，采集功能不可用而已（该行为经过 QA 实例实测：拒绝授权后键入品位、试听、整谱播放与保存均正常）。

### 系统声音采集一直"启动中"然后超时？

这是已知问题：CoreAudio HAL 调用（`AudioDeviceCreateIOProcIDWithBlock`）可能超时（日志可见 `MACH_RCV_TIMED_OUT` / `0x10004003`）。应用的对策是：tap 创建在后台串行队列、10 秒有界等待、超时即取消并恢复界面；**超时后录谱、播放、保存与退出仍然可用**。处理建议：断开重连蓝牙音频设备、关掉独占音频的其他应用、重启 CoreAudio（注销重登）后重试；麦克风／声卡输入不受此问题影响。

### 切换系统录音授权时为什么要求 Touch ID？

macOS 对系统音频录制授权的保护；应用不能也不会绕过该认证。取消认证时授权保持原状。

### 蓝牙耳机下识别或采集异常？

蓝牙输出的采样率可能是 44.1 kHz 而非 48 kHz。实现按 aggregate 协商后的名义采样率分析，默认输出时钟或采样率变化时会停止当前系统采集并提示重新开始——按提示重新开始即可。

### 为什么采集时会弹出"佩戴耳机"提示？

麦克风与扬声器同时使用时，伴奏会从扬声器串入麦克风。**麦克风下的扬声器串音无法保证消除**，带声音的练习请佩戴耳机。

## 编辑器

### 输入品位 12 只得到 1 或 2？

两位品位输入的组合窗口是 **0.8 秒**：连续按 `1` `2` 得到 12；间隔太久则第二次按键开始新的组合。验收记录中"新建文档直接按 1、2 得到 12 品"是标准行为。

### 键盘没反应？

键盘桥在**谱面点击后**才请求第一响应者。先点击谱面上的音符或位置；在文本字段输入时快捷键不会被拦截（这是设计而非故障）。

### 出现"延音未连接"警告？

你勾选了延音（L / tieToNext）但还没录入续音。这是**允许的中间状态**：可以先录延音起点再录目标；播放只持续已明确记谱的时值，不猜测续音。

### 保存被拒绝并显示容量／重叠错误？

校验失败会拒绝当前操作且**不移动另一声部**：检查小节容量是否超出（4/4 = 3840 ticks）、同声部事件是否重叠、同弦是否跨声部持续音冲突、击勾弦滑音的目标品位方向是否正确。

### 撤销把标题文字也撤销了？

不会——文本字段使用自己的原生文本撤销，曲谱历史只记录曲谱编辑逆操作。早期版本存在该缺陷（`NSTextStorage` 取得曲谱撤销管理器），已通过向底层文本存储提供 `nil` 撤销管理器修复，并有异步记账回归用例。

### 改谱后播放的还是旧版本？

有效改谱、撤销和重做会停止本文档旧播放会话；下次播放使用最新曲谱。播放验证失败时保留当前选择和目标位置并显示原因。

## 跟练与判定

### 为什么和弦段落不评分？

应用只实现**单音评分**。同声部和弦、死音、击弦、勾弦、滑音、推弦、揉弦明确跳过单音评分；这是文档化的算法边界，不是 bug。整和弦判定请使用"和弦练习"栏目的整和弦识别判定。

### 同一个音连续出现，第二次不判定？

**重复同音需要新起音**。保持按住不拨弦不会产生新的判定；重新拨弦即可。起音检测有 90 ms 不应期，自然延音不会被误判为新起音（该行为经过真琴复测："每次拨弦只推进一个"）。

### 总是显示抢拍或拖拍？

依次检查：跑一次**跟拍校准**（吸收系统偏移与跟拍习惯，历史真琴校准为 +4 ms，含人为偏差）；佩戴耳机排除串音；确认结果里的**有符号偏移**方向——持续为正说明你在拖拍，负值说明抢拍。±150 ms 是默认容差，分析宽限 350 ms 只补偿分析延迟，不扩大容差。

### 校准为什么失败了？

校准只接受其自身播放时钟的起音，每拍最多计一次；至少需要三组匹配的预期／实际起音。采集断开、另一窗口接管播放、时钟或速度改变都会取消校准；无法获得音频时钟会直接报错而不是无限等待。

## 和弦识别

### 识别结果为什么慢半拍？

结果以 **0.34 秒分析窗口的中心时间**为准，比实际弹奏晚约 0.2–0.5 秒；判定切换还需 2–5 帧证据。让六根弦一起响足半秒最容易稳定。

### 显示"无和弦"？

输入 RMS 过低（静音门槛 0.004）、宽带噪声、或声音不在 205 模板词表内（鼓、人声等）。确认采集来源正确、音量足够、环境安静。

### 为什么我的开放调弦和弦识别不出来？

识别假设标准十二平均律音高，**不识别非标准调弦下的开放和弦名**。整体轻微失谐可自动补偿（−50…+50 音分范围内估计，−32 音分实测通过），但开放 G/D/E 这类改变音程结构的调弦超出模型范围。

### 识别准确率是多少？

离线证据：合成 180 个首选按法 177 个正确命名；实时冒烟五段进行全部正确。**真琴与麦克风条件下的准确率未测量**——项目明确不报告虚构准确率。

## 曲库与数据

### 数据保存在哪里？怎么备份？

`~/Library/Application Support/Guitarget/MyLibrary/`：`library.json` 清单 + 每谱 UUID 子目录（`score.guitarget` 与音频副本）。曲库弹窗底部可在 Finder 显示；**备份复制整个目录**。详见《数据存储位置与备份》。

### 导出的谱为什么没有声音文件？

普通导出**只包含谱和歌词**；音频副本与 Apple Music 链接属于本机曲库。需要音频请连同备份目录一起迁移。

### 移除曲库条目失败？

移除前需要**先保存并关闭**该曲库文档窗口。另外曲库中的名称是管理用名称，谱内标题由编辑器修改，两者独立。

### 提示"library.json 丢失"？

清单文件缺失但目录内仍有文件时应用会报错并**保留现有文件**，不会静默重建。恢复最近的 `MyLibrary/` 备份即可。

## 播放与音频

### 没有声音？

检查窗口底部**声音来源**的输出设备选择（输出独立于输入）；设备断开会停止播放并恢复默认输出。全应用合成音与附加音频**互斥播放**：另一窗口开始播放会暂停当前音频并保留位置。

### 为什么选了附加音频就不能改谱？

这是**只读演奏模式**的设计：录音独立计时，谱位由输入单音智能跟随；禁止改谱与点击定位是为了保证跟随状态一致。切回"曲谱合成"即恢复编辑，原曲谱与编辑历史保留。

### 附加音频和谱面对不上？

音频时间与实际弹奏谱位**独立**：应用不下载受保护音频、不做原声与谱面自动同步。录音的前奏、自由速度或编配差异需要你自己对齐——谱面跟随的是你的演奏，不是录音进度条。

## Apple Music

### 点了"在音乐中打开"没反应或无法播放？

应用只保存链接并移交给系统"音乐"应用；曲目与完整播放取决于**地区、账号及订阅状态**。确认链接来自"分享 → 复制链接"，且"音乐"应用已登录可播放该曲目的账号。

## 功能范围

### 支持 Guitar Pro 导入或多乐器轨吗？

不支持。应用只实现本地六弦吉他、单音评分与整和弦识别判定；无 Guitar Pro 导入、无自动转谱、无逐音复音转录评分。

### 有 iOS / Windows 版吗？

Guitarget 主应用是 macOS 应用。你正在阅读的这个文档 App 同时支持 macOS 与 iOS。
