# 项目介绍

这份说明给第一次打开仓库的人，也给几个月后的自己。只写代码里已经有的东西。最后一节的边界是对着实现和现有文档归纳的，仓库里没有单独的 TODO 列表，也没有排期。

日常怎么用、怎么构建，在仓库根目录的 [README](../README.md)。这里补结构、数据和练习到底记了什么。

## 应用长什么样

`Sources/Guitarget/App/GuitargetApp.swift` 建了三个场景：

1. **学习室**，窗口标识 `learning`，标题「Guitarget · 学习室」。最小约 1020×680。侧栏是 `LearningSection` 的十项：指板、音阶、CAGED、三和弦、和弦库、调音器、和弦识别、合奏、和弦练习、曲谱。
2. **曲谱文档**，`DocumentGroup` + `GuitarScoreDocument`。新建、打开、最近文件和关闭前的保存确认走系统文档机制。
3. **声音设置**，选输入和输出设备。

所有窗口共用一个 `AudioService.shared`。谁在播放由 `ownerID` 决定，新的播放会停掉上一个。菜单「声音」里可以停掉全部播放（⌘.）或停止采集。

学习室副标题是「从一个音，到一首歌」。跟练卡片的标题是「把听见的，变成弹出的」。这些句子是界面文案，功能范围以代码为准。

## 曲谱数据

一份谱是一个 `GuitarScore`：

- `version` 必须是 1，否则 `ScoreIO.decode` 拒绝。
- `title`。
- `tuning`：六个 MIDI，从第 1 弦（高音 E）到第 6 弦。标准调弦是 `[64, 59, 55, 50, 45, 40]`。
- `timeSignature`：2/4、3/4、4/4、6/8。别的拍号容量记为 0，校验会先报错。
- `bpm`：20–300，默认 80。6/8 也按四分音符计速。
- `measures`：至少一小节。数组顺序就是播放顺序。

每小节恰好两个声部，`melody` 和 `bass`。事件有 `startTick`、`rhythm`、`notes`，可选 `lyric`。空的 `notes` 是休止。音符有弦 1–6、品 0–24、力度 0–1、技巧和 `tieToNext`。击弦、勾弦、滑音要有 `targetFret`。

四分音符恒为 **960 ticks**。4/4 一小节 3840 ticks。谱上的秒是 `absoluteTick × 60 / (960 × bpm)`，这是记谱速度下的时间，不含预备拍，也不去对齐录音。

`tieToNext` 只连接同声部、同弦同品、正好接在后面的音。延音在调度里合成一次拨弦。还没写上续音的延音可以保存，播放只持续已经写下的时值。同弦重叠、超出小节、两个声部在同一根弦上的持续音打架，都是错误，修改会被拒绝。

文件是 UTF-8 JSON，扩展名 `.guitarget`，类型标识 `com.guitarget.score`。`ScoreIO` 只读写这份结构。字段表和一份最小例子在 [曲谱格式](score-format.md)。

`Examples/GenerateExamples.swift` 生成 `Fingerstyle.guitarget`、`F-Major.guitarget`、`Techniques.guitarget`。入门六首既在 `StarterScores` 里，也导出在 `Examples/MyLibrary/`。

## 时间怎么排

`ScoreScheduler.notes` 把两个声部展开成 `ScheduledNote`：绝对 tick、MIDI、延音合并后的结束点。休止空隙用 `restGaps` 补，不要求每个空拍都写成休止事件。

播放路径是：曲谱 → 调度 → `ScoreRenderer` → `AVAudioSourceNode` → `AVAudioEngine` → 选定的输出设备。旋律和低音在同一次回调里，按同一个 48 kHz 样本计数走。变速改的是 ticks 和样本的关系，不改拨弦音高。预备拍、节拍器、循环区间和声部静音都在这次播放上。

钢弦声音是 Karplus–Strong 一类的物理模型：每根弦一条延迟线，加上拨片、琴体共振和一点混响。击弦／勾弦留着弦的振动，滑音改延迟，推弦到半音或全音，揉弦做调频，闷音加阻尼，死音是短噪声。种子固定，测试可以复现。细节和没声称的部分在 [音频实现](audio.md)。

合奏的四种伴奏也是普通 `GuitarScore`，由 `JamBuilder` 在本地生成，可以存成文档。进行是：

| 样式 | 和弦 | 默认 BPM |
| --- | --- | --- |
| 民谣分解 | I–V–vi–IV | 80 |
| 流行切分 | I–V–vi–IV | 100 |
| 小调慢板 | i–VI–III–VII | 68 |
| 十二小节布鲁斯 | I7–IV7–V7 | 92 |

循环包住的是这次伴奏播放。推荐音不打分。

## 练习、反复、进度

跟练的核心是 `PracticeEngine`，一个不依赖界面的状态机。目标来自 `PracticeTarget.from`：选定声部里每个要拨的事件一个目标。延音的续音不再单独评分。同声部和弦、死音、击弦、勾弦、滑音、推弦、揉弦带 `skipReason`，不打单音分。

两种模式：

- **弹对再前进**（`waitForCorrect`）。音高落在 ±25 音分内，并连续稳定约 120 ms，才进入下一个。和前一个音相同，或刚听完示范，必须有新起音。跳过的目标要手动继续，记成「手动继续」或「跳过」。
- **按节拍跟练**（`timed`）。目标时间是 `startedAt + tick / 960 × 60 / bpm`。起音相对拍点超出 ±150 ms，记抢拍或拖拍；音高不对记音高错误；窗口里没有起音记漏音。后面的音已经响了，可以结束前一个漏音的等待，避免一个短音卡住后面一串。分析可以晚到 350 ms，这个宽限不把起音容差放大。

`PracticeSummary` 统计已评分、正确、漏音、跳过和平均绝对时值（毫秒）。进度条是 `当前序号 / 目标数`。示范期间暂停判定，并在时间轴上补上示范占用的时间。另一扇窗口抢走播放时，练习会暂停，并暂时交还静音、速度和节拍器，回来再恢复。

跟拍校准 `InputLatencyCalibration` 要至少三对「该响的时刻 / 实际起音」，取绝对值不超过 1 秒的中位数。这个数包含人的误差。校准值加进 `PracticeConfiguration.inputLatency`，从测到的起音里减去。

和弦练习是包在外面的另一层，`ChordPracticeSession`：

- 训练方式：看图、听示范后演奏、限时记忆。记忆秒数在界面上是 2–20，默认 5。
- 牌组只抽大和弦、小和弦，或两者混合。根音可多选。轮数 1–40，默认 8。同一组里尽量不让相邻两张是同一个和弦。
- 逐弦判定把按法拆成一串单音，交给 `PracticeEngine`。它证明这些音高依次出现过，不证明弦位，也不证明和弦同时响着。
- 整和弦判定听 `ChordFrame`。根音和性质与目标一致，并在一次新扫弦之后保持 0.3 秒，这一轮算通过。低音不同（C/E）只提示转位。
- 自评是「清晰、熟练」「还需练习」「跳过本轮」，和自动结果分开存。
- 用过提示会记在这一轮上。

附加音频时的跟谱是 `ScoreFollower`。它不靠节拍器，位置停在最后确认的音。错音、静音和单纯过时间都不前进。漏掉少量音后，最多向前看三个可识别音，并用后面连续两个音把位置找回来。和弦、死音和连续变音没有音高证据，要等后面的单音才跨过去。默认音准容差是 ±35 音分，比跟练的 ±25 宽一点；稳定时间同样约 120 ms。

### 什么会留下来

会留下的：

- 曲库：`~/Library/Application Support/Guitarget/MyLibrary/library.json` 和每个 UUID 目录里的谱、音频副本、Apple Music 链接、备注。QA 包标识是 `com.guitarget.qa`，曲库改到 `Guitarget QA/MyLibrary/`。
- 几个界面偏好，经 `@AppStorage` 进 UserDefaults：每行小节数、是否显示联动指板、调音器预设、A4 基准。
- `.guitarget` 文档本身，跟任何文件一样由你保存。

不会留下的：

- `PracticeEngine.results`、和弦练习的各轮结果、和弦识别页最近 12 条、调音器那 8 秒曲线。都在内存里，窗口关了就没了。
- 没有任何按天排列的复习队列，也没有「这首谱练到第几遍」的档案。

所以进度在产品意义上，就是这一轮走到第几个音、这一组和弦对了几轮。它还不是学习记录。

## 听音

采集二选一：麦克风或外接声卡的 input tap，或者 CoreAudio process tap（某个 App，或系统混音并排除 Guitarget 自己）。分析在单独队列上做，实时回调里只拷样本。

单音是 YIN，大约 65–1500 Hz。音高帧的 `timestamp` 是分析窗中心，`onsetTimestamp` 是独立的起音时刻。评分用起音时刻，不用「算法刚算完」的时刻。

和弦识别和 YIN 并行，读同一块环形缓冲。自研 FFT、对数频率映射、律制补偿、Lawson–Hanson NNLS、谐波残留抑制，再把 205 个模板（15×12 个和弦、12 个强力和弦、12 个单音、「无和弦」）送进一个带惯性的 HMM。思路来自 NNLS chroma，实现是纯 Swift，没有 Accelerate，也没有训练权重。算法步骤、合成测试范围，以及「还没有在真琴上测过准确率」这件事，写在 [音频实现](audio.md)。

识别高亮的指板位置是「这个 MIDI 还出现在哪些品」，不是「你按下的那根弦」。

## 转换器

`convertor/` 不参与 App 构建。它把 Guitar Pro 源谱转成应用已经认识的 v1 `.guitarget`，每个源版本一份文件，同版本的吉他轨按时间叠在一起。主解析器读不了的旧 GP，可以走一份私有 TuxGuitar 运行时，说明在 `convertor/README-legacy.md`。GPX 或更新的 GP 若解析不了，就在报告里记失败。

用法、合谱规则和曲库整理脚本在 [convertor/README.md](../convertor/README.md)。那里的示例路径是作者自己机器上的目录，换一台电脑要改。成品必须过 `ScoreIO.decode` 才写出。Python 依赖留在转换器的虚拟环境里。

## 开发和验收

只构建、不打开：

```sh
./script/build_and_run.sh --build-only
```

关掉正在运行的应用之后，可以做一次编辑器和音频自检。它走原生编辑状态和 UndoManager，并写出六弦数值诊断、`steel-string-demo.wav`、`reference-a4.wav`。它不启动采集，也不把算法输出说成真琴准确率。

```sh
./script/build_and_run.sh --build-only
open dist/Guitarget.app --args --self-check "$PWD/artifacts/app-self-check.json"
```

`script/stage_qa.sh` 打一个独立包 `artifacts/Guitarget QA.app`，可执行名 `GuitargetQA`，标识 `com.guitarget.qa`，避免动到主应用里的文档。这个包只给开发用。默认会打开并做同样的 `--self-check`。脚本还接受 `--hardware-smoke` 和 `--system-isolation-smoke`。

应用还认这些启动参数，都写在 `GuitargetAppDelegate` 里：`--hardware-smoke`、`--microphone-restart-smoke`、`--chord-recognition-smoke`、`--guitar-capture`、`--system-isolation-smoke`。引导采集会把帧写到会话目录，并明确 `scientificAcceptanceClaimed: false`。

`.vscode/launch.json` 里有 Debug / Release 两个 Swift 启动项，目标是包里的可执行产品 `Guitarget`，不是已经套好的 `.app`。要图标、文档类型和麦克风说明，用 `script/build_and_run.sh`。

验收当时记了什么、没测什么，以 [验收记录](acceptance.md) 为准。自动化测试覆盖的是数学关系和合成音，不等于真琴识别率或物理延迟。

## 从代码看出的边界（推断，不是排期）

下面这些是现有实现自己划出的线，或文档里已经写明「还没有测／还没有做」的点。把它们当成路线图会过头：仓库里没有对应的 TODO 注释，也没有说下一版要做哪一条。

- 单音评分和跟谱都不处理同声部和弦、死音和连续变音技巧。等待模式下要手动继续；跟谱则等下一个能识别的单音。代码把这写成当前规则，没有写成即将补上的接口。
- 没有逐音的复音转录评分。整和弦练习只核对识别出的根音和性质。
- 附加音频的播放时间和谱面位置互不换算。Apple Music 只保存链接。
- 练习成绩不写盘，也没有跨天的重复调度。
- 应用里不能导入 Guitar Pro，没有多乐器轨，没有自动转谱。旁边的转换器覆盖它能解析的 GP，解析失败就报告，不在应用里兜底。
- 拍号、三连音和文档版本的范围就是校验器允许的那一组。
- 和弦练习的牌组只有大、小三和弦。和弦库里的另外十三种可以查、可以听，不进这套抽卡。
- 调音器的 Drop D、DADGAD 等预设不写回曲谱的 `tuning`。
- 麦克风收到扬声器的声音时，没有串音消除。
- 真琴准确率和物理输入延迟没有被说成已经测完。`docs/acceptance.md` 里有关记录写着 `realGuitarAccuracyMeasured: false`；历史跟拍校准包含人的偏差。离线和弦测试用的是合成按法，不是一把真吉他。
